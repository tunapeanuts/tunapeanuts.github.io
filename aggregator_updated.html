DEXでSwapしたトランザクションを見ていると，1inchやParaSwap，KyberSwapなどの名前を見かけることがある．これらはDEX Aggregatorと呼ばれるものである．そもそもDEXとAggregatorは何が違うのか，それぞれどのような仕組みになっているのかを整理する．

そもそもAggregatorとは？

例えば，1 ETHをUSDCに交換するとする．Ethereum上にはUniswapやCurve，Balancerなど複数のDEXが存在するが，それぞれが異なる流動性プールを持っているため，同じ1 ETHを交換しても受け取れるUSDCの数量は異なる．

当然，一番多くUSDCを受け取れるDEXを利用したいが，Swapする度にすべてのDEXを比較するのは面倒である．そこで登場するのがDEX Aggregatorである．

Aggregatorとは，複数のDEXやその他の流動性供給元を横断的に調べ，より有利な交換経路を探索し，その経路を実行するための仕組みである．

旅行予約サイトが複数の航空会社を比較して航空券を探すのと似ている．ざっくり言えば，以下のような関係にある．

  • DEX：トークンを交換する場所．
  • Aggregator：トークンをどこで，どのように交換するかを決める仕組み．

Aggregatorは単なる価格比較ではない

Aggregatorの面白いところは，必ずしも1つのDEXを選ぶわけではないということ．

Split Routing（分割経路）

AMM型のDEXでは，大量のトークンを交換すると流動性プール内の資産の比率が変化するため，交換価格が悪化することがある．取引自体によって価格が変化することをPrice Impactと呼ぶ．そこで，1つのDEXでまとめて交換するのではなく，複数のDEXに交換量を分割するという方法が考えられる．

例えば100 ETHを一度に交換するよりも，複数のプールに分割したほうが最終的に多くのUSDCを受け取れる場合がある．

Multi-hop Routing（複数段階の経路）

また，ETHをDAIに直接交換するよりも，一度USDCに交換してからDAIに交換したほうが有利な場合もある．

つまり，Aggregatorは単にDEXごとの価格を比較しているのではなく，交換レート，流動性，Price Impact，ガス代，手数料，経由するトークン，取引の分割割合などを考慮して交換経路を探索している．このような経路探索の仕組みはSmart Order Routing（SOR）と呼ばれる．

アルゴリズム的に見ると，トークンを頂点，交換可能なプールを辺としたグラフ上の経路探索・最適化問題に近い．ただし，交換量によって辺のコストが変化し，経路を分割することもできるため，単純な最短経路問題というわけではない．

Aggregatorの内部構造

では，これらの経路探索はすべてスマートコントラクト上で行っているのだろうか．一般的なAggregatorでは，経路探索と実際のSwapは別の場所で行われる．

Off-chain：経路探索

APIサーバなどが各DEXの状態を調べ，交換経路を計算する．その経路を実行するためのcalldataなどを生成し，ウォレットに返す．

On-chain：経路の実行

Aggregation Routerなどのコントラクトがcalldataに従ってDEXや流動性プールを呼び出し，Swapを実行する．同一チェーン上の通常のAggregator Swapでは，複数のDEXを経由しても1つのトランザクション内で交換を完結できる．

要するに，どの経路で交換するかを考える部分と，その経路を実行する部分が分かれているということ．経路探索自体をオンチェーンで行う必要はない．なお，ERC-20の利用権限が未設定であれば，別途Approveが必要になる場合がある．

AggregatorとRouterの違い

ここまでAggregatorの話をしてきたが，そもそもRouterとは何が違うのだろうか．両者は似たような言葉に見えるが，システムの異なる側面を指している．

Routerとは？

例えば，UniswapでWETHをDAIに交換する際に，USDCを経由するとする．Routerを利用すれば，ユーザが個別にPoolを呼び出すことなく，複数のPoolを経由するSwapを1つのトランザクションで実行できる．

つまり，オンチェーンのRouterは複数のコントラクトへの呼び出しを仲介し，指定された経路に沿ってSwapを実行するコントラクトである．

AggregatorにもRouterがある

一方，1inchのようなAggregatorはUniswapだけでなく，CurveやBalancerなどの異なるDEXの流動性も交換経路の候補にする．1inchの場合，Pathfinderが経路探索を担当し，Aggregation Routerなどがその経路を実行する．

Uniswapでも複数のPoolやバージョンを横断する経路探索が行われている．したがって，経路探索を行うかどうかだけでAggregatorとRouterを区別することはできない．

ただし，Routerという言葉は厳密に標準化されているわけではない．Smart Order Routerのように，オフチェーンで経路探索を行うプログラムをRouterと呼ぶこともある．

ここまでの内容を整理すると以下のようになる．

  • Pool：実際の流動性を提供する．
  • Router（オンチェーン）：交換経路に沿って処理を実行する．
  • Routing Engine：交換経路を探索・最適化する．
  • Aggregator：複数の流動性供給元を集約し，経路探索から取引実行までを提供する．

AggregatorとRouterは対立する概念ではなく，システム全体とその構成要素の違いとして捉えるのがよさそう．Aggregator自身もRouterを持つということ．

主要なDEX Aggregator

1inch v6

1inchは代表的なDEX Aggregatorである．Classic SwapではPathfinderと呼ばれる経路探索アルゴリズムを利用して交換経路を探索する．v6はここではAggregation Routerのバージョンを指している．

Ethereum MainnetのAggregation Router V6は以下のアドレスにデプロイされている．

0x111111125421ca6dc452d289314280a0f8842a65

Etherscan - Aggregation Router V6

代表的な swap() では，以下のような構造体を受け取る．

struct SwapDescription {
    IERC20 srcToken;
    IERC20 dstToken;
    address payable srcReceiver;
    address payable dstReceiver;
    uint256 amount;
    uint256 minReturnAmount;
    uint256 flags;
}

srcToken が入力トークン，dstToken が出力トークンである．amount は入力数量，minReturnAmount は最低受取数量を表す．別途渡される実行データを用いてExecutorが具体的な交換処理を行う．

ParaSwap v6.2（Velora）

ParaSwap（現Velora）も複数の流動性供給元から交換経路を探索するAggregatorである．オンチェーンで交換を実行する主要なコントラクトはAugustus Swapperと呼ばれる．

v6.2には以下のような交換関数がある．

swapExactAmountIn(...)
swapExactAmountOut(...)
swapExactAmountInOnUniswapV3(...)
swapExactAmountInOnCurveV1(...)

汎用的な交換関数では，以下のような情報を扱う．

address srcToken;
address destToken;
uint256 fromAmount;
uint256 toAmount;

srcToken が入力トークン，destToken が出力トークンである．Exact Amount InとExact Amount Outでは固定する数量が異なる．1inchと目的は基本的に同じであるが，コントラクトの構造やcalldataの形式が異なる．

KyberSwap

KyberSwapはKyber Networkが提供するDEX Aggregatorである．他のDEXやマーケットメーカーなどの流動性を利用して交換経路を探索する．代表的なRouterの1つに MetaAggregationRouterV2 がある．

Aggregator APIにおける経路探索のリクエストでは，例えば以下のようなパラメータを指定する．

tokenIn  = WETHのアドレス
tokenOut = USDCのアドレス
amountIn = 1000000000000000000

これは1 WETHをUSDCに交換する場合の例である．この情報から交換経路を探索し，Routerに渡す実行データを生成する．

0x AllowanceHolderとMetaMask Swap

残りの2つは先ほどの3つとは少し異なる視点で理解する必要がある．

0x AllowanceHolder

0xはDEX Aggregationの機能をAPIとして提供するプロトコルである．他のDAppも0xのSwap APIを利用することでトークン交換機能を組み込むことができる．

0xのSwap API v2では，ERC-20の利用権限に関してAllowanceHolder方式とPermit2方式が用意されている．

AllowanceHolder方式ではAllowanceHolderに対してApproveを行い，Permit2方式ではPermit2に対してApproveした上で署名を利用する．Settlerに直接Approveするわけではない．

AllowanceHolder自体は経路探索アルゴリズムではなく，トークンの利用権限と取引実行を仲介するコントラクトである．経路探索を行うのは0xのSwap API側である．APIでは入力トークンを sellToken，出力トークンを buyToken として指定する．

MetaMask Swap

MetaMask SwapはMetaMaskウォレットに内蔵されているトークン交換機能である．MetaMaskはDEXだけでなく，他のAggregatorやマーケットメーカーからも見積もりを取得し，ユーザに交換経路を提示する．つまり，Aggregatorをさらに集約するMeta-Aggregatorとしての性質を持っている．

DEXが増えたためAggregatorが生まれ，Aggregatorが増えたためMeta-Aggregatorが生まれたと考えると分かりやすい．
