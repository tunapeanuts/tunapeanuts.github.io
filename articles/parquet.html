大量のデータを分析する際に，CSVではなくParquetという形式でデータを保存することがある．そもそもParquetとは何なのか，CSVとの違いや内部構造，なぜデータ分析に向いているのかを整理する．

そもそもParquetとは？

Parquet（パーケット）とは，大量の構造化データを効率よく保存・分析するための列指向のファイルフォーマットである．Apache Parquetとして公開されており，CSVやJSONと同じくデータを保存するための形式の1つである．

ファイル形式拡張子保存形式
CSV.csv行単位・テキスト
JSON.jsonテキスト・階層構造
Parquet.parquet列指向・バイナリ

重要なのはParquetはデータベースではないということ．PostgreSQLやBigQueryはデータを管理・検索するシステムであるが，Parquetはあくまでデータの保存形式である．検索や集計を行う場合はPandasやDuckDBなどのツールを利用する．

CSVと何が違うのか？

例えば，以下のようなユーザ情報を保存することを考える．

IDNameAgeBalance
1Alice201000
2Bob252000
3Carol303000

CSVでは1行分のデータをまとめて保存する．

ID,Name,Age,Balance
1,Alice,20,1000
2,Bob,25,2000
3,Carol,30,3000

一方Parquetでは，同じ列に属するデータをまとめて保存する．

行指向・列指向DBの違いと同じ考え方である．例えば全ユーザの平均年齢を計算する場合，必要なのはAgeの列だけである．

SELECT AVG(age)
FROM users;

通常のCSVではファイル全体を走査する必要があるが，Parquetでは必要な列だけを読み込むことができる．数億件のデータに対して分析を行う場合，この差が大きくなる．

Parquetの内部構造

実際にはParquetはファイル全体を単純に列ごとに分割しているわけではない．Row Groupという単位で行を分割し，その内部で列指向の保存を行っている．

構成要素役割
Row Group一定数の行をまとめた論理的なグループ
Column ChunkRow Group内の特定の列のデータ
PageColumn Chunkを構成する符号化・圧縮の単位
File Metadataスキーマ，データの位置，統計情報など

例えば100万行を10万行ずつに分けた場合，10個のRow Groupができる．それぞれのRow Groupには各列に対応するColumn Chunkが存在し，さらにその中にPageが存在する．

ファイルの末尾にはメタデータが保存されている．読み込み側はこの情報を利用して必要なColumn Chunkの位置を特定できるため，ファイル全体を順番に読み込む必要がない．

なぜParquetは高速なのか？

Parquetがデータ分析に向いている理由は主に以下の4つである．

Column Pruning（列の読み飛ばし）

分析に必要な列だけを読み込む仕組みである．

SELECT age
FROM users;

Age以外の列を読み込む必要がない．列数の多いデータに対して一部の列だけを使う場合に特に効果がある．

Predicate Pushdown（条件の押し下げ）

Parquetには列の最小値や最大値などの統計情報を保存できる．対応する分析エンジンはWHERE句などの条件をファイルの読み込み処理に押し下げ，条件に一致する可能性のないRow Groupを読み飛ばせる．

SELECT *
FROM users
WHERE age >= 60;

ただし，統計情報が存在することや分析エンジンがこの最適化に対応していることが前提である．データの並び方によっても読み飛ばせる範囲は変わる．

圧縮効率が高い

同じ型や似た値が連続して保存されるため，効率よく符号化・圧縮できる．例えばトークン名を保存する列があるとする．

ETH, ETH, ETH, USDC, USDC, ETH

辞書符号化（Dictionary Encoding）を用いると，以下のように表現できる．

辞書：0 = ETH, 1 = USDC
データ：0, 0, 0, 1, 1, 0

同じ文字列を何度も保存する必要がなくなる．さらにSnappyやZstandardなどの圧縮方式を利用することもできる．

データ型を保持できる

CSVは基本的に値を文字列として表現する．一方Parquetでは，スキーマとデータ型を保持できる．例えば以下のような形である．

transaction_hash : string
block_number     : int64
gas_used         : int64
timestamp        : timestamp

読み込み時に毎回テキストから数値へ変換したり，データ型を推定したりする必要がない．

実際にどうやって利用するのか？

PythonではPandasやPyArrowを利用することでParquetを扱うことができる．

pip install pandas pyarrow duckdb

CSVからParquetへの変換

import pandas as pd

df = pd.read_csv("transactions.csv")

df.to_parquet(
    "transactions.parquet",
    compression="zstd",
    index=False
)

Parquetの読み込み

df = pd.read_parquet("transactions.parquet")

特定の列だけを読み込む

df = pd.read_parquet(
    "transactions.parquet",
    columns=["from_address", "timestamp"]
)

全ての列をDataFrameに読み込んでから不要な列を削除するのではなく，ファイルの読み込み時点で必要な列を指定できる．

DuckDBでParquetに直接SQLを実行する

DuckDBを利用すれば，データベースに事前にインポートすることなくParquetファイルに対してSQLを実行できる．

import duckdb

df = duckdb.sql("""
    SELECT
        from_address,
        COUNT(*) AS tx_count
    FROM read_parquet('transactions.parquet')
    GROUP BY from_address
    ORDER BY tx_count DESC
""").df()

Parquetがデータの保存を担当し，DuckDBが検索や集計を担当しているという関係である．

比較項目CSVParquetPostgreSQL

かなりざっくり言えば，Parquetとは，大規模なデータ分析に特化した列指向かつ圧縮効率の高いCSVのような存在と理解するとよいと思う．

ただし，Parquetはバイナリ形式であるため，CSVのようにテキストエディタで直接読むことはできない．また，既存レコードを個別に更新する場合は基本的に対象ファイルの書き直しが必要となる．頻繁な個別更新を行うシステムよりも，大量のデータを蓄積し，必要な部分を抽出・集計する用途に向いている．
